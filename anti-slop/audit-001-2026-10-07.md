# Anti-slop audit 001

Tanggal: 2026-10-07  
Cakupan: pembacaan statis `src/`, `public/`, `README.md` dengan aturan anti-slop. Aplikasi tidak dijalankan dalam audit ini, jadi perilaku runtime dan breakpoint belum diverifikasi.

## Temuan

### 1. HIGH — Dialog tidak dapat ditutup dengan Escape

**Aturan:** R-32 (akses keyboard), R-26 (perilaku interaktif).  
**Berkas:** `src/Sheet.svelte:59-64`, `src/PersonForm.svelte:94-100`.  
Kader dan form tampil sebagai panel modal dan punya tombol tutup serta penutupan melalui klik backdrop, tetapi tidak menangani tombol Escape. Pengguna keyboard tidak memiliki cara yang disediakan untuk menutup modal tersebut dengan Escape.

### 2. HIGH — Tidak ada status loading saat operasi cloud

**Aturan:** R-27 (keadaan UI).  
**Berkas:** `src/App.svelte:91-114`.  
Simpan dan ambil cloud berjalan secara asynchronous, tetapi UI tidak menampilkan status proses atau mencegah aksi berulang selama permintaan berjalan. Hanya hasil berhasil/gagal yang diberitahukan setelah operasi selesai.

### 3. LOW — Alasan untuk keputusan visual utama belum dicatat dengan cukup spesifik

**Aturan:** R-31 (alasan desain harus ditulis).  
**Berkas:** `src/app.css:1-55`, `src/app.css:198-264`.  
Komentar CSS menyebut gaya besar dan kontras untuk lansia, tetapi tidak mendokumentasikan alasan pilihan palet hijau, tipografi system default, radius, dan bayangan. Sulit menilai konsistensi keputusan tersebut dari kode saja.

## Catatan verifikasi

- Tidak ada perubahan pada kode aplikasi.
- Tidak ada klaim PASS untuk kontras, reflow seluler, interaksi lengkap, atau console karena aplikasi tidak dijalankan dan diuji.
- Prioritas mengikuti tier aturan: hard gate = HIGH, quality lock = LOW.
